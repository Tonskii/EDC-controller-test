WHAT MAKES THE C3-400 PLUS OPEN (learned from ZKBio CVSecurity, 2026-10-21)
- userauthorize: ONE ROW PER DOOR, AuthorizeDoorId = door number 1..4 (NOT a bit mask like 15),
  plus DevID = the controller's DevProperty ID (1). A mask (15) is accepted with Return=0 but
  every swipe gives EVENT 27 "card/user not registered".
- mulcarduser: CardNo in LOWERCASE hex, exactly as the swipe event shows it (1d0456).
  UPPERCASE (3876F6) is stored but never matches → EVENT 27.
- user: CardNo= (empty) Pin Password Group StartTime EndTime Name= (empty) SuperAuthorize=0 Disable=0
- extuser: Pin FunSwitch=0 FirstName=<name> LastName=
- DATA DELETE SuperAuthorize Pin=<pin>
The server now sends all of this automatically — the Swagger bodies below are all you need.

HOW TO USE
- Pull the latest code first, then start the server and let the controller reconnect.
- Swagger: endpoint → "Try it out" → paste the JSON → Execute.
- Every answer contains "commandId": check it with GET /api/commands/{id}?waitSeconds=15
  → want "status": "Succeeded", "returnCode": 0 (queries return the row count).
- "sn" may be left empty while only one controller is connected.
- Add ?preview=true to see the exact command without sending it.
- Test data: PIN 1001 · card 0x1d0456 (as the swipe event shows it) · time rule 1 · doors 1–4.

 STEP 0 — PREPARATION
---------------------------------------------------------------------
0.1  GET /api/devices
     → "heartbeats" increasing, "devId": 1, "devIdSource": "controller DevProperty table".
     If devId is missing: POST /api/tables/{table}/query  table = DevProperty
     If you stored 190 earlier, remove it: PUT /api/devices/{sn}/devid  sn = AJU8261200103, value empty.

0.2  Controller clock:  POST /api/device/sync-time   (time rules use the controller clock)

0.3  Optional clean start (removes ALL users, cards, access, names on the controller):
     DELETE /api/users/all   confirm = true

1a   24h rule 1, exactly like ZKBio CVSecurity — PUT /api/timerules

  "timezoneId": 1,
  "everyDay": ["00:00-23:59"]

     Expected:
     DATA UPDATE timezone TimezoneId=1[TAB]SunTime1=2359[TAB]SunTime2=0[TAB]SunTime3=0[TAB]MonTime1=2359
       ... [TAB]SatTime1=2359 ... [TAB]Hol1Time1=2359 ... [TAB]Hol3Time1=2359[TAB]Hol3Time2=0[TAB]Hol3Time3=0

1b   Office hours rule 2 (optional) — PUT /api/timerules
{
  "sn": "AJU8261200103",
  "timezoneId": 2,
  "weekdays": ["07:00-12:00", "12:30-17:00"],
  "weekend": ["08:00-12:00"]
}
     (07:00-12:00 = 700<<16 + 1200 = 45876400; GET /api/timerules/decode/{value} decodes any value)

---------------------------------------------------------------------
 STEP 4 — SWIPE
---------------------------------------------------------------------
     EVENT 0  "Normal open after verification" door=1 IN pin=1001 card=1d0456   → OK
     EVENT 27 "Card/user not registered" → card not in lowercase hex, or no per-door access row
     EVENT 22 "Illegal time zone"        → outside the time rule / controller clock wrong
     EVENT 29 "validity expired"         → validFrom/validUntil

---------------------------------------------------------------------
5.1  POST /api/users/query      → user ... pin=1001 password=1234 ... name= superAuthorize=0 disable=0
5.2  POST /api/cards/query      → mulcarduser pin=1001 cardno=1d0456 losscardflag=0 cardtype=0

 STEP 6 — DELETE
---------------------------------------------------------------------
6.1  Everything of one user in one call:
     DELETE /api/users/{pin}/complete     pin = 1001, sn = AJU8261200103
     Expected (in this order):
     DATA DELETE userauthorize Pin=1001      (all doors)
     DATA DELETE mulcarduser Pin=1001        (all cards)
     DATA DELETE extuser Pin=1001

6.2  Single parts:

                          (the CardNo must match the stored text exactly, incl. case — to remove an
                           old UPPERCASE row use cardNo empty = all cards of the user)
     Time rule 2          DELETE /api/timerules/{timezoneId}   timezoneId = 2
     Rule 1               only with allowRule1 = true (other users reference it)

6.3  Check it is gone: repeat STEP 5 — PIN 1001 and card 1d0456 must be gone; swipe → EVENT 27.


---------------------------------------------------------------------
 RAW COMMANDS (POST /api/raw) — rules
---------------------------------------------------------------------
- Fields separated by [TAB] (any case: [TAB], [Tab], [tab]), records by [LF].
- Do NOT paste real tab characters into the JSON (invalid JSON → 400).
- Field names are case-sensitive: CardNo, not Cardno. The answer warns about wrong names,
  spaces instead of tabs, and uppercase hex card numbers.
{
  "sn": "AJU8261200103",
  "command": "DATA UPDATE userauthorize Pin=1001[TAB]AuthorizeTimezoneId=1[TAB]AuthorizeDoorId=1[TAB]DevID=1",
  "label": "Raw access door 1"
}
